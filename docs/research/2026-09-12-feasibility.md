# 피키클래스 앱 이식 조사

조사일: 2026-09-12. 이 문서는 구현 완료 보고가 아니라 실제 확인 결과와 구현 결정의 근거다.

## 목표와 유지할 경험

`thsvkd/pudufu-recorder`와 거의 같은 데스크톱 UI를 유지한다.
로그인 → 내 강의 선택 → 회차 선택 → 배속·폴더 설정 → 저장·변환 진행 흐름이 원래 목표다.
참조 코드 버전은 `073514e436a15c8d8c63386e020c2d155ecbf29d`다.

## 실제 확인 결과

- 제공된 `.env` 계정으로 Chrome 로그인과 독립 HTTP 세션 로그인을 각각 확인했다.
- 마이클래스에 수강 항목 6개가 표시된다.
- 4개 영상 강의의 HTML에서 회차 링크를 각각 21, 22, 21, 7개 확인했다.
- 다른 2개 항목에서는 영상 회차 링크가 없었다. 이 사실만으로 미디어 부재나 전체 자료 유형을 단정하지 않는다.
- 영상 강의 4개에서 첫 회차의 Kollus HTML 응답을 각각 확인했다.
- 각 응답의 `kollus-player-launcher` 요소에 있는 `:player-policy` JSON의 `is_encrypted` 값이 모두 boolean `true`였다.
- 확인 범위는 강의별 첫 회차 4개다. 모든 71개 회차를 검사한 것은 아니다.
- Chrome에서는 Kollus Player V3 미설치와 플레이어 초기화 실패 안내가 표시되었다. 설치나 미디어 재생 성공 검증은 하지 않았다.
- 강의 HTML에 공식 플레이어용 다운로드 연결 코드가 존재한다. 코드 존재는 사용자에게 해당 기능이 활성화되었다거나 다운로드가 승인된다는 증거가 아니다.
- 영상 파일 다운로드, MP4 변환, 보호 해제, 화면 녹화, 소프트웨어 설치는 수행하지 않았다.

계정, 쿠키, JWT, 서명된 재생 URL, 주문 식별자는 이 문서에 저장하지 않는다.

## 판단

기존 프드프의 일반 MP4/HLS 입력을 FFmpeg로 변환하는 경로는 현재 확인된 DRM 영상에 그대로 적용할 수 없다.
Kollus의 공식 오프라인 다운로드는 암호화 상태를 유지하는 저장이며, 일반 MP4 내보내기와 다르다.
따라서 원래 목표의 핵심 저장 기능에는 제약이 확인되었고, UI·목차 앱 또는 공식 오프라인 연동으로 바꾸는 것은 명시적인 범위 결정이 필요하다.
플레이어 설치 요구만으로 DRM을 단정하지 않았으며, 별도의 `is_encrypted` 응답을 근거로 판단했다.

독립 검토에서도 이 판단을 확인했다. 다만 공식 채널 API의 동명 필드와 플레이어 내부 정책 속성의 스키마가 완전히 같다는 별도 증명은 없다. 직접 관찰한 암호화 정책과 보안 플레이어 요구를 함께 근거로 삼는다. 공개된 일반 MP4 내보내기 경로는 확인되지 않았다.

로그인·목차 UI 준비는 기존 승인 범위에 포함되지만, 조회 전용 앱을 원래 다운로드 앱의 완성본으로 간주해서는 안 된다.

## 사이트 연동 시 확인한 명세

1. 로그인 화면을 GET하여 세션을 시작한다.
2. `/ajaxProc.php`에 multipart POST: `type=userCheck`, `userID`, `userPasswd`.
3. 성공 응답의 `code=200` 및 `msg`를 확인한다. `msg`는 로그에 남기지 않는다.
4. `/member/login_ok.php`에 POST: `etc=msg`, `login=5`, `auto_login=2`, `login_go=/`.
5. 로그인 페이지를 Referer로 사용하는 정상 요청 헤더를 포함한 세션에서 마이클래스 조회 성공을 확인했다. 헤더별 필수 여부는 따로 분리 검증하지 않았다.
6. `/order/lectureRoom/?type=onList`의 강의실 링크를 읽는다. 강의 식별자와 수강 항목 식별자가 함께 필요하다.
7. 강의 상세의 `a.video_row`와 `iframe#myClass`를 확인한다. 문서 내 `video_url` 데이터에는 회차별 재생 링크가 있다.
8. Kollus 재생 응답의 정책을 검사한다. 플레이어 페이지 주소를 영상 파일 주소로 취급해서는 안 된다.

위 명세는 이번 관찰 시점에 한정한다. 사이트 변경·수강 만료·추가 인증·세션 만료를 오류로 처리해야 한다.

## 기존 앱의 재사용 경계

| 파일 | 변경 범위 |
| --- | --- |
| `pudufu/client.py` | 피키클래스 로그인·수강 항목·목차·지원 여부 확인 클라이언트로 교체 |
| `pudufu/models.py` | 기존 UI 필드는 보존하되 수강 항목 식별자 및 지원 상태 표현 필요 |
| `ui/core_bridge.py`, `ui/app.py` | 클라이언트, 앱 제목, 환경변수, 설정 키, 저장 경로 분리 |
| `ui/login_view.py` | 브랜드와 아이디 로그인 문구 변경 |
| `ui/courses_view.py`, `ui/lesson_select_view.py` | 기존 카드·회차 선택·설정 레이아웃 재사용 가능 |
| `ui/progress_view.py` | 실제 지원하는 작업에 한해 진행률·오류 표시 재사용 |
| `pudufu/recorder.py` | 비암호화 입력이 확보될 경우에만 연결. HLS 단독 입력 분기와 인증 전달 보완 필요 |
| `pudufu/ffmpeg_tool.py` | 앱 전용 데이터 경로 분리. FFmpeg 준비를 로그인 전에 강제하지 않도록 조정 검토 |
| `pudufu/velopack_update.py`, `scripts/build.py`, `pyproject.toml` | 프드프 업데이트 경로 및 앱 식별자 제거·분리, 비밀정보 패키징 검사 유지 |

원본 UI의 비밀번호 기억 기능은 SharedPreferences에 값을 저장하므로 그대로 복사하지 않는다.
새 배포 경로가 준비되기 전에는 프드프 저장소를 향한 자동 업데이트를 켜지 않는다.

## 다음 단계의 선택지

1. 기존 UI로 로그인·목차 조회를 먼저 구현하고, DRM 회차의 MP4 저장 미지원 상태를 명시한다.
2. 피키클래스가 제공하는 공식 Kollus 오프라인 저장의 실제 활성화 여부를 먼저 검증한다. 결과는 암호화 파일이며 MP4 배속 변환이 아니다.
3. 일반 MP4 저장이 필수라면 구현을 보류하고, 서비스가 제공하는 공식 비암호화 다운로드 가능 여부를 확인한다.

위 선택지 제시 후 사용자가 목표를 구체화했다: 파일을 확보하고 전사까지 완료해야 한다. 따라서 조회 전용 앱이나 Kollus 안에서만 가능한 오프라인 시청은 완료 조건을 충족하지 않는다.

## 추가 확정 요구: 파일 확보 후 전사

- 기존 앱과 거의 같은 화면·강의/회차 선택 흐름을 유지한다.
- 결과 파일은 일반 미디어 처리 도구가 읽을 수 있어야 한다. 암호화 캐시를 단순히 저장하는 것으로 완료 처리하지 않는다.
- 확보된 미디어의 음성을 텍스트로 전사하는 단계까지 앱의 범위에 포함한다.
- 전사 입력은 원래 속도의 음성을 우선 사용한다. 배속 영상 저장과 전사 작업은 별도 단계로 구분한다.
- 실제 강의 한 회차에서 입력 파일의 재생·음성 읽기와 전사 결과를 확인하기 전에는 전체 목표 달성을 주장하지 않는다.
- 현재 제약은 전사 엔진이 아니라 DRM 콘텐츠로부터 일반 처리 가능한 입력 파일을 확보하는 경로가 확인되지 않았다는 점이다.
- Kollus 설치만으로 일반 파일 추출·전사가 가능해지는 것은 아니다. 공식 재생 기능과 원본 내보내기 기능을 구분한다.
