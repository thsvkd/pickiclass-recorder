# 작업 오케스트레이션 결정

## 환경과 선택

Orca CLI의 설치 및 버전 일치 안내를 확인했다. `orca status --json` 결과는 앱 미실행, 런타임 `not_running`, `reachable=false`였다.
사용자는 특정 Orca 런타임 사용을 지정하지 않았으므로 새 런타임을 시작하지 않고 현재 세션의 기본 에이전트 협업 도구를 선택했다.

단일 실행자 방식과 독립 검토를 병행하는 방식을 비교했다. 로그인 세션과 사이트 조사는 공유 상태가 많으므로 주 에이전트 한 명이 담당한다.
계정이 필요 없는 기존 소스 검토는 별도 에이전트가 독립적으로 수행한다. 구현이 시작되면 파일 소유권을 명확히 나눈 뒤 검증 결과를 통합한다.

이는 작업 의존성에 근거한 선택이며, 반복 실험으로 속도나 비용의 최적성을 입증한 정책이 아니다.

## 실제 역할과 결과

| 역할 | 범위 | 확인 방법 | 결과 |
| --- | --- | --- | --- |
| 주 에이전트 | 계정·마이클래스·Kollus 정책 조사 | 정상 Chrome 로그인 및 독립 HTTP 세션, 정책 JSON 확인 | 6개 항목, 영상 강의 4개 첫 회차 모두 `is_encrypted=true` |
| 독립 검토 에이전트 | 프드프 코드 재사용·결합점 조사 | 공개 소스의 함수와 호출 경로 검토 | UI 재사용 맵, HLS 단독 분기·쿠키 전달·앱 식별자 문제 확인 |
| 독립 검토 에이전트 후속 | DRM 판단과 공식 오프라인 저장 차이 검토 | 공식 문서와 관찰 범위 비교 | 일반 MP4 경로 미확인, 공식 오프라인은 암호화 유지, 전체 회차로 일반화 불가라는 검토 결과 통합 |

검토 에이전트에는 `.env` 읽기, 브라우저 조작, 제품 코드 수정, 커밋·푸시를 허용하지 않았다.
실제 로그인과 정책 확인 결과를 완료 판단의 근거로 삼았으며, 에이전트의 이식 가능 의견만으로 영상 저장 성공을 주장하지 않았다.

## 진행 조건

- 일반 미디어 입력 확인 성공: 기존 UI를 이식하고 회차 하나 저장·변환부터 검증.
- DRM 확인: MP4 변환 가능이라고 표시하지 않으며, 다른 제품 범위로 변경하기 전에 사용자의 선택을 받음.
- 어떤 경우에도 계정·세션·재생 토큰은 보고서나 저장소에 기록하지 않음.
