# 피키클래스 파일 저장·전사 구현 계획

승인된 목표: 기존 Flet 앱과 거의 같은 화면으로 강의를 선택하고, 사용 가능한 미디어 파일을 저장한 뒤 전사까지 완료한다.
참조: `docs/research/2026-09-12-feasibility.md`.
현재 작업 폴더는 기존 코드가 없던 독립 프로젝트다. 참고 저장소는 `.research/pudufu-reference`에 격리했고, 원래 `.env`는 수정하지 않는다.

## 작업 소유권과 검증

1. 주 에이전트: `pickiclass/client.py`, 모델 확장, CLI, 정상 재생·자료 조사, 통합 검증.
   - 사이트의 정상 로그인 요청을 따르고, 계정과 토큰을 로깅하지 않는다.
   - 강의/회차/정책을 파싱하고, 암호화된 입력을 일반 미디어 URL로 오인하지 않는다.
   - 합성 HTML 파싱 테스트를 먼저 작성해 실패를 확인한 뒤 구현한다. 실제 계정은 별도의 읽기 전용 실행으로 검증한다.
2. UI 작업자: `ui/`, `main.py`, UI 관련 테스트.
   - 기존 카드와 선택 화면 유지, FFmpeg 선행 설치 제거, 비밀번호 지속 저장 제거, 이전 앱 자동 업데이트 비활성화.
   - 로컬 파일 전사 진입점 추가. 백그라운드 처리 및 취소/오류 표시.
3. 전사 작업자: `pickiclass/transcription.py`, `tests/test_transcription.py`.
   - `Transcriber.transcribe(source, output_dir=None, on_progress=None, cancel=None)` → 결과 경로 객체.
   - faster-whisper CPU int8, 한국어 기본, 외부 업로드 없음. 원래 속도 오디오를 입력으로 사용.
   - TXT/SRT/JSON 출력, 타임스탬프, 취소, 실패 시 불완전 결과 처리, 파일명 충돌 보호를 테스트.
4. 통합: 사용 가능한 오디오 저장 경로와 전사를 실제 파일로 연결해 검증한다.
   - 공식 자료·자막, 비암호화 미디어, 정상 재생 오디오 저장을 순서대로 확인한다.
   - 보호 정책 변경, 인증 우회, 다른 앱 소리의 무단 수집을 하지 않는다.
   - 실제 강의 입력 확보가 막히면 합성/샘플 테스트를 강의 성공으로 표시하지 않는다.

## 완료 조건

실제 선택한 강의의 처리 가능한 영상/음성 파일과 비어 있지 않은 전사문이 생성되어야 한다.
조회 UI나 암호화 캐시만으로 완료 처리하지 않는다. 필요한 사용자 설치·추가 입력이 생기면 독립 작업을 완료한 뒤 정확한 단계만 안내한다.
